# Toybox Mayhem (Godot port)

Godot 4.7 (GDScript, Jolt physics) port of Toybox Mayhem. The original TypeScript/three.js/Rapier game is the source of truth for behaviour:
`C:\Users\adive\Documents\Data Science\Python\School IT\AP CSP Unit 3\ToyboxMayhem-update3\toybox-mayhem\src\`. Each GDScript file names the `.ts` file it ports.

Everything is built in code (no imported art or audio): `scenes/main.tscn` -> `scripts/main.gd` -> `scripts/game.gd`.

Godot executable: `C:\Users\adive\Downloads\Godot_v4.7-stable_win64.exe\Godot_v4.7-stable_win64_console.exe`

- Compile-check every script: `sh tools/check.sh`
- Headless match test: `Godot --headless --path . -- --autotest=<ffa|tdm|takeover|conquest|training> --seconds=20 --map=<bedroom|backyard|toycity>` (training also parks a dummy in front of you and prints `[training]` stats)
- Screenshots (needs a window, not headless): add `--shots=<dir>`; menu screens with `--screen=<play|loadout|settings|controls|login|main|resume>`; `--screen=switch` checks Start match on another map auto-starts after the reload; `--screen=padtest` checks controller A presses the highlighted button; `--screen=traversal --map=<id>` rides every jump pad and zipline and prints `[traversal] N failures`; `--screen=interiors --map=toycity` checks every Toy City storey is walkable and reachable street -> door -> stairs -> roof
- Perf debugging (windowed autotest): prints `[perf]` (script sections, `outside` = engine/render time) and `[gpu]` (measured GPU ms) every 20 frames; `--tris` dumps the heaviest meshes; `--exp=shadow,glow,msaa,lights,vm,transp,fog,cc,sky,half` switches features off. GPU timings on this laptop vary 2-4x between identical runs (power state), so compare interleaved runs.
- Pools (particles, chips, decals, projectiles) set `visible_instance_count` to the highest live slot; keep that when touching them.
- Static plastic is batched per finish, not per colour: `Mats.vc_twin` + vertex colours in `Batcher`.
- Training Range (`Modes.MODES.training`, not in MODE_ORDER): passive bots (`Bot.passive`), endless reserve, no end, `Game.training_weapons` overrides from the pause menu's Try a blaster; never records stats/coins.
- Note: `--screen=switch` saves the other map as the selected map in the real save file; set it back afterwards.
- Maps: bedroom, backyard, toycity (Toy City is original to this port; Kitchen Clash was removed). Elevators are gone: every map uses jump pads + ziplines (`scripts/world/traversal.gd`, data in each arena's `PADS` / `ZIPS`; zip points are feet positions, cable 2.6 m above; rooftop ends sit 1 m above the roof just inside the edge).
- Nav: pads/zips are passed to `NavGraph.build` as connectors so pruning keeps rooftops/the shelf; real links come from `Traversal.link_nav` (`pad`/`zip` fields). Cache key includes a hash of the connectors and `Phys.static_fingerprint()` (all static colliders), so geometry edits rebuild it automatically.
- Toy City walls have real windows (`_wall(..., windows)`: "home" / "shop"; each panel = 2 jambs + sill + header (rests on the jambs) + a glass pane; facade textures are drawn `plain`). Glass never counts as a support. Cars, the bus, phone box, truck cab and house window are glass pieces too.
- Toy City buildings are hollow (`ArenaToyCity._building`): doors per `doors`, a floor per storey, switchback ramp stairs per `stairs` ending in a roof hatch. Keep stair lanes so a nav sample column (grid x/z = -33.2 + 1.6k) falls inside each 1.8 m lane, or bots can't find the stairs.
- Online play (port of the TS `src/net/`, protocol v105, not compatible with the TS game): host/guest over a relay. The host's game runs the real match and sends 20 Hz snapshots + events; guests move their own toy, send 30 Hz states, and send hit *claims* the host applies (`Combat.local_auth` = full / claims / visual). Code: `scripts/net/` (`net_client.gd` = autoload `Net`, which survives the scene reload a map switch needs; `host_session.gd`, `guest_session.gd`, `snapshot.gd`, `roster.gd`), online bits in `game.gd` (search `online`), menus `online_screen` / `lobby`. Guests switch to the host's map while in the lobby; messages wait in `Net.inbox` during the reload.
- Relay: `server/worker.js` (Cloudflare Worker + one Durable Object per room). `cd server && npm run dev` runs it locally on ws://127.0.0.1:8787 (no account needed); `node test-relay.mjs [url]` checks it; `npm run deploy` publishes it (needs `npx wrangler login`). The game's default server is `Net.DEFAULT_SERVER`; Settings `serverUrl` or `--server=<url>` override it.
- Online test (two headless copies, relay running): `Godot --headless --path . -- --online=host:1 --room=T1 --server=ws://127.0.0.1:8787 --autotest=<mode> --seconds=30 --map=<id> [--lobbymap=<id>] --name=Hosty` and, a few seconds later, `... -- --online=guest --room=T1 --server=... --seconds=24 --name=Guesty`. Each prints `[online]` lines (messages, states/claims/shots, scoreboards, team scores) to compare. The guest saves the host's map as its selected map.
- Export: `Godot --headless --path . --export-release "Windows Desktop" build/ToyboxMayhem.exe` (templates in %APPDATA%/Godot/export_templates/4.7.stable, Windows x86_64 only).
- Release: `sh tools/build_installer.sh` exports and builds `build/ToyboxMayhem-Setup.exe` with Inno Setup (`installer/toybox_mayhem.iss`, per-user install, keeps saves on uninstall). Version = `config/version` in project.godot (bump it per release). Icon: `assets/icon/toybox_icon.{png,ico}`. GitHub: github.com/adirkverma25-maker/toyboxmahem (`main` is this Godot project; the TS game is in its history). README.md is the players' install guide and links `releases/latest/download/ToyboxMayhem-Setup.exe`, so the release asset must keep that name.
- Destruction (`scripts/world/destruction.gd`, spec `docs/superpowers/specs/2026-11-15-destruction-design.md`): breakable pieces added with `Builder.breakable_box` / `breakable_brick` (class glass 8 HP = any hit / soft 220 / hard 700; hard ignores bullets; blasts x`Combat.BLAST_STRUCT`=6). Pieces are merged per group into one mesh, own colliders on `Phys.WORLD|PIECE`; opts `rests` (falls with what holds it up), `studs`, `uv_origin` (world-space texture so panelled walls line up). Debris chunks are on `Phys.CHUNK` (never toys). Nav: `NavGraph.build_async` ignores pieces, then stores `blockers` per node/link (closed until broken). Online: piece damage follows `Combat._auth` (guest own hits -> `gpiece` claims, host sends `break` events + `bk` list in snapshots every 2 s), protocol 101. Floors/roofs/stairs/corners/frames never break. Tests: `sh tools/test_destruction.sh` (unit) and `sh tools/destruct_all.sh` (`--screen=destruct` on every map: blows a wall, checks the route and a bot through it; `--shots=` saves pictures). Keep breakable structures off nav grid lines (as with Toy City stairs) or bots can't stand inside them. `jolt_physics_3d/motion_queries/use_enhanced_internal_edge_removal` is on so movement doesn't snag on panel seams.
- Classes (spec `docs/superpowers/specs/2026-11-16-classes-loadout-design.md`): `Cfg.CLASSES` (light 100 HP x1.10 speed, 1 of dash/grapple; medium 150 HP x0.90, 1 of shield/cloak; each has its own guns and gadget list). `Actor.set_class()` at spawn sets `cls`, `max_health`, `class_speed` (not `speed_mult`, that's the turbo pickup). Loadout = class + ONE weapon (a gun, or the class's melee weapon: `Loadout.gun()` may return sword/spear -> `Actor.melee_held`, no blaster) + ONE ability (Q, `ability1`) + ONE gadget (F, `gadget` bind); `Loadout` keeps per-class picks in the `loadouts` setting and migrates 1.1 saves (old primary decides the class). Bots: `Game.assign_bot_classes` mixes classes per team, `Bot.set_class` nudges the personality (Lights hunt hurt targets 12 s, Mediums hold 10-22 m and retreat below 40%). Training dummies are Mediums; Try a blaster sets `training_gun` (its class applies on respawn). Online: guests send `cls` in gstate, the host applies it on the first state of each life. Gadgets: `Cfg.GADGETS` (fragGrenade, pyroGrenade for Lights; explosiveMine, pyroMine for Mediums; the other names in each class list show as coming soon). Hold the gadget key to aim (`Player.gadget_aiming`; `GrenadeArc` draws the simulated arc + a landing ring sized to the blast / fire / mine trigger), release throws via `Abilities.try_gadget` -> `Combat.throw_gadget` (projectile system: visuals `grenade`/`mine`; mines stick and trigger by proximity, max 2; `explosion.fire` leaves burning patches in `Combat._fires`; `explosion.pieceDamage` = wall damage: one frag / explosive mine breaks the panel it hits). Online: `on_gadget` -> `ggadget` / `gadget` events, replayed as visual. `--screen=gadgettest` checks them. Bots throw grenades at targets 7-24 m and drop mines when holding/retreating; bots get rattled when hit (reaction delay, shaky aim, body shots; melee hits scare them into retreating). Unit tests: `sh tools/test_classes.sh`.
- Melee (spec `docs/superpowers/specs/2026-11-16-melee-gravity-design.md`): Spring Punch is gone. Taking the melee weapon as your weapon: fire swings `Cfg.MELEE[Cfg.CLASSES[cls].melee]` (sword: Lights, spear: Mediums) via `Abilities.try_melee` -> `Combat.melee` (hits every enemy whose feet/chest/head is in the zone; chips pieces). Models: `scripts/weapons/melee_model.gd` (viewmodel + toy rig). `Actor.melee_t` / `melee_ready_at` (snapshot `MELEE_T`, plus `CLS`). Gravity 22, jump velocity 7.87 (jump height still 1.4 m). Sword 0.3 s, spear 0.7 s; keyframed swings in `MeleeModel.VIEW_KEYS` / `ARM_KEYS` (first person / toy arm). `--screen=meleetest` swings at a dummy and (with `--shots=`) saves pictures.
- Sniper: Thunderspring (85 body / 153 head = one-shot head through full shield, fast ADS, 2.5x default scope) fires a fast "slug" projectile with slight gravity plus a tracer streak. `--screen=snipertest --map=toycity` fires it at a full-shield dummy 40 m away; `--screen=loadout:<weaponId>` screenshots the loadout with that blaster selected.
